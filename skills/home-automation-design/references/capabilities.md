# 能力补充与缺失降级

## 能力账本

同一物理设备可以有多个集成，每项能力选一个主来源和明确备用，不要求整台设备所有功能来自同一个集成。记录：需求、主/备用实体、可用性与反馈、命令入口、单位、实际验收、失效处理、导出身份。

以 Xiaomi Home 作为基础接入时，先验收实际能力。遇到缺口再评估 MIoT、Gateway3、设备原生集成、Matter、HomeKit Device 等：

| 所需能力 | 补充时应检查 |
|---|---|
| 扫地机房间/分区命令 | 当前实体是否有 Clean Area、有效映射，或 MIoT room_mapping/厂商地图接口；不能只看机器在 App 能清扫。 |
| 低延迟按键/传感器事件 | 网关是否兼容 Gateway3 或其他本地方案，是否需要特定硬件/固件；核对事件去重、长按/双击、重连语义。 |
| 特定模式/风速/属性 | 原生/MIoT 服务与枚举、读写反馈、型号限制。全局服务存在不代表目标设备支持。 |
| 本地可用性 | 是否仍依赖厂商云授权、地图下载或网关中枢；协议转换本身不会让云端设备变成本地设备。 |

先关联物理身份与能力，避免同设备重复自动化、反馈回路和苹果家庭重复图标。不同来源的灯状态、功率、推断开关要设权威关系和迟滞，不能双方把对方的推断再当新真值。迁移先保留回滚，确认没有消费者再退役旧集成。

## 缺失与故障分开

| 缺少的证据/执行器 | 可选替代 | 需要保留的限制 |
|---|---|---|
| 无存在雷达，只有 PIR | 延长离开确认、人工活动保持、门/设备使用证据 | 静坐可能漏检，不用于强制关灯的等价无人证明。 |
| 无床压/床区 | 手动睡眠、明确起床退出、时间与多信号组合 | 关门/关灯只能弱推断，不声称知道人在睡。 |
| 无门窗磁 | 使用设备反馈、人工确认或停用需闭合证明的动作 | 发出关闭命令不等于已闭合。 |
| 无照度计 | 太阳高度/日出日落、已知室内灯态、人工亮度偏好 | 室内遮光、天气和朝向影响精度，避免固定时间强关灯。 |
| 无功率计 | 设备原生运行态、按键活动、手动计时 | 不同设备的运行模式及停机反馈要验收。 |
| 无本地雨滴 | 天气预警与通知、保守的人工关窗 | 无法保证本地及时防雨，不能假装等价雨滴联锁。 |
| 无手机在家/路由器追踪 | 门锁出入、多人体与用户一键离家 | 访客与多人需处理，不用某人离开推出所有人离家。 |
| 无温湿度/CO2 | 保留人工控制或定时通风，按实际安全条件限制 | 不伪造环境数值，不无证据声称空气质量达标。 |
| 无完整设备反馈 | 有界动作、等待合理运动时间、人工确认 | 状态置信度低，不能反复强制运动或写假状态。 |
| 无机器人房间 API | 厂商接口、可验证的自定义分区适配；最后才是基础启停 | 原生房间、坐标划区和脚本开关不是同一能力。 |
| 无稳定网络/云端 | 本地手动开关及设备自带保护 | 聊天 Agent 不能承担持续的实时安全控制。 |

已配置传感器故障时转为未知/降级，通常保持必要照明、睡眠和正在活动保护，停用依赖其明确证明的危险动作；恢复后稳定一段时间再重新参与。根据风险给出有界降级，不能“故障就永远全部打开”或“故障就当无人”。

## 设备反馈异常适配

某型号可能一直报 opening/closing；建立型号/固件白名单、原始状态、命令时间、合理运动时间、位置/限位等可用证据，并标注“推断完成”。必须保留异物/运动超时的退出路径。不能把所有窗帘 opening 都解释为完全打开，也不能抹掉原始状态掩盖故障。

功率倍率/单位修正应有设备说明或实测依据，修正后的业务实体保持唯一权威，保留原始值用于诊断；展示小数位与实际分辨率分开。未确认的降水单位不能自动换成毫米，取绝对值也不是万能修复。

主备切换以主源失效/过期、备用健康为条件；两者不可用时明确不可用，不能永远显示旧缓存。阈值、时区、温标、方向与缺失值语义均需一致。观测覆盖不足时报告证据范围，不能用少量快照断言稳定。
