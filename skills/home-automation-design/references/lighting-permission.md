# 房间光照许可变量

在需要按环境亮度自动补光的房间，用一个可见布尔变量统一表达“当前是否允许自动补光”，让占用、模式、定时和恢复入口读取同一结果。它只参与决策，不直接代表灯的开关状态；已有可靠实现可沿用，不为采用此方法强制更换自动化工具。

## 变量与职责

| 项目 | 含义与写入来源 |
|---|---|
| 光照许可，例如 `input_boolean.study_light_permit` | `on`＝光线不足，允许自动补光；`off`＝光线充足，禁止普通自动逻辑把全灭的照明打开。只由光照判断 owner 更新。 |
| 光照输入及健康 | 明确传感器、单位、有效范围、观测/上报语义；单独记录 valid，不能把布尔许可当成健康证明。 |
| 开灯阈值与迟滞 | 各房可调、单位 lx；可用 `input_number`。迟滞是差值，不是最终的高阈值。 |
| 自动照明启停 | 独立的人工设置，不能与计算出的光照许可混用。 |
| 模式、人工保持与无人截止时间 | 独立记录；经共同仲裁决定实际动作，许可变化不能取消这些保护。 |

HA 原生实现可使用 Helper 加状态检查自动化；已有引擎可使用等价的共享变量及可见状态。只有一个光照判断 owner 写许可，房间规则读取它。若需人工跳过光照判断，另设明确的强制/恢复自动入口及期限，不用随手翻转计算结果冒充人工保持。

## 迟滞与输入有效性

设开灯阈值为 `T`，非负迟滞差值为 `H`，照度为 `L`：

```text
输入有效且 L < T      → permit = on
输入有效且 L > T + H  → permit = off
T ≤ L ≤ T + H        → 保持上次有效许可
输入无效              → valid = false；不按 0 lx 更新许可
```

例如 T=100 lx、H=800 lx，则低于100允许补光，高于900禁止普通自动重亮；这只是说明计算方式，不是所有房间的推荐数值。阈值、迟滞及必要的稳定时间按摆放、采光与灯光影响选择，边界值在本契约中保持。

许可可以保留上次显示，但自动开灯前必须同时读取当前输入有效性。新安装没有历史许可且处于迟滞带时，尚无证据推导许可；初始化、故障恢复及重启对账需记录来源，不以 Helper 默认 on 或恢复值代替有效照度证据。不要因传感器长时间数值不变就自动认定故障，也不要只凭 HA 最近状态时间认定读数新鲜；按设备实际报告方式定义健康。

## 开灯、保持与关灯分开

普通占用照明从全灭开灯，至少同时满足：自动化启用、当前有可靠占用、光照输入有效且许可为 on、模式允许、无有效人工抑制，并通过睡眠及跨房间等已选择的保护。夜灯或特定任务灯若使用不同许可，单独定义，不能默默旁路保护。

占用到来、照度下降、模式变化、人工保持到期和启动对账均唤醒同一判断。许可刚变 on 但房间无人不自动开灯；有人已在房间而后来变暗，也无需等待新的有人事件。

按周期采样照度的家庭也可以在接受新的窗帘目标时立即检查。先用同一采光规则计算并提交补光许可，再唤醒照明仲裁。即使许可值相同，新的窗帘目标也应触发一次开关灯检查。动作仍读取占用、人工保持和活动模式。目标位置与实际回报如何衔接见[窗帘与采光](curtains-and-daylight.md)。

灯已亮时，许可 off **不等于关灯命令**。不要因为灯照到照度计，使许可变 off 就立即熄灯。人工选定场景可按约定强制应用；已亮灯后的工作/日常分区切换按活动和人工保持判断，不因反照而自动取消。人工调暗后是否允许补充其他灯，也须明确范围。

无人关灯独立检查持续可靠无人、截止时间、当前模式、人工保持及邻区保护，不能附加“光照许可必须 off”。否则夜里一直昏暗的空房会无法关灯。人在场但天亮后的关灯/调暗是另一项可选规则，需另行确认，并处理传感器反照及任务照明。

## 人工操作与重新进入

人工开灯、人工关灯、人工选择全关模式及系统自身反馈分别处理。固定30分钟等保持期限不是通用要求；既有家庭先保留已确认行为，未确定时只询问影响行为的必要选项：

- 手动开灯后是否仍参与无人关灯？是立即按无人计时、保持到指定时间，还是必须人工解除？
- 手动关灯后，抑制到期、确认离房后解除、还是用户解除？选择“离房解除”时定义持续无人证据，防止一次传感器抖动马上重亮。
- 离开再进入能否开灯，取决于上项是否已解除，以及当时光照、模式和占用条件；不能把“有人事件”写成无条件清除人工保持。
- 夜间全关后的床区翻身是否保持黑暗、哪些床外分区允许微光、微光如何关？按睡眠契约处理，不能套用普通离房重置。

可选的事件释放策略如下，启用前按房间确认作用范围和优先级。

- 手动开灯后保留灯态，直到下一次确认无人并完成自动关灯，或新的手动关灯接管。补光采样、区域变化和自动场景遵守此保持。房间在开灯时就明确无人时，从这次手动意图起重新计时。
- 手动关灯后暂停自动重亮，直到次日日出已过且房间达到现有连续无人时长。两个条件都成立才释放，房间未知会中断连续无人计时。记录本地日出对应的绝对时间并持久化，允许新的手动操作接管。
- 摄影、直播等活动可在整个模式期间保持当前灯态，退出时重读条件。家庭可选择在确认全屋无人时提前清空全部手动照明保持并执行离家关灯。明确此动作与活动模式的优先级，以及返家后的模式恢复方式。

把同一盏灯的墙壁按键、HA、灯组和苹果家庭操作映射到实际受控范围。用命令上下文和预期回报识别规则自行发出的开关灯，避免将其反馈记为手动操作。实际设备、云端或第三方控制无法可靠标注来源时，记录歧义并验证回报的归因。

人工保持与无人计时若同时运行，到期后按两个条件的实际截止时间重读，不机械串加时长。自动化自身服务反馈不能再次建立人工保持；动作排队期间收到新人工意图，应使旧动作失效。

## 缺传感器与验收

没安装照度计时可选择太阳/时段/窗帘等弱替代，或不用光照限制、仅按占用和模式自动照明；先明确选择与局限。已配置传感器故障不能自动解释成“未安装，取消限制”。多个传感器先选择参考位置和融合方式，不直接对不同位置取平均。

最少验证以下行为，并区分离线推演与实物反馈：

| 场景 | 应有结果 |
|---|---|
| 低于阈值、迟滞带内、超过高阈值、等于边界 | 分别允许、保持、禁止、保持；不抖动。 |
| 明亮且全灭时有人进入；已有人后变暗 | 前者保留灭灯，后者通过其余保护后补光。 |
| 许可原为 on，随后照度不可用；新安装没有历史许可 | 不凭旧许可或默认值证明昏暗，不写假照度。 |
| 开灯使照度升高；人在场切工作/日常 | 不因反照熄灯，切换遵守当前活动和人工保持。 |
| 夜里许可持续 on，但房间明确无人达到截止时间 | 按无人及保护规则关灯，不要求环境变亮。 |
| 人工开/关灯、短暂离开返回、保持到期 | 与约定的保持和释放方式一致，不被巡检或新有人事件抹掉。 |
| 重启、未知占用、新人工指令到达旧延迟任务前 | 对账真实输入和持久期限；未知不证明无人；旧动作失效。 |

交付时展示每房许可、有效性、照度、阈值/迟滞、阻止原因及人工恢复入口。可见许可和启停设置分别命名，避免用户把“光线不足”误读成“整个自动化已开启”。
