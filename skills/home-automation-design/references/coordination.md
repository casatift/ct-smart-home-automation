# 模式、全屋协调与执行

## 模式契约

按实际需要分别建模全屋基准（在家/离家、日常/夜间）、房间活动（用餐/烹饪/观影/洗浴/书桌专注）、睡眠、人工保持、故障/维护；不强制每家启用全部模式。可以用少量 helpers 展示，但内部不要把所有维度穷举为一个巨大枚举。卧室复用与学习/工作选择见 [房间与照明](rooms-and-lighting.md)。

每种模式定义：进入证据、退出证据、是否需持续、来源、优先级、保持/失效时间、重启是否恢复、恢复目标。恢复目标常是“重新按当前全屋状态计算”，并非无条件恢复历史日常。来源分为用户明确选择、设备物理操作、推断；不可把所有状态变化都当用户主动操作。

典型仲裁顺序可为：硬件安全互锁 → 安全范围内的明确人工意图 → 已确认睡眠或正在活动保护 → 全屋基准 → 节能/美观。让家庭需求决定例外；不要把活动模式设计成无法人工退出的永久锁。

人工夜间可保持到用户退出或约定晨间恢复事件；短暂离开和再次有人不应立即洗掉。晨间触发可用日出偏移或用户作息；有人睡觉、空房但门关、未知占用三种情况分别处理。门磁只能说明开闭，不能替代床区占用或睡眠确认。缺床传感器时用用户约定的睡眠保持和人工起床确认等较弱策略，说明无法保证同等精度。

## 共同决策与跨房间保护

先确认用户选择的保护依赖，再选实现工具。以下是可选设计模式，不是每个家庭必须启用的联动：

- 客餐厅共享照明：如选择餐厅保护客厅，餐桌占用/用餐保持可阻止客厅关灯或降至约定亮度以下。保护覆盖无人计时、模式变更、电视结束、光照变化、全屋同步和巡检等全部写入入口。是否主动开灯另行选择；未启用则各区独立。
- 厨房/餐厅：做饭、油烟机及炉具运行可作为烹饪活动证据，不能默认代表用餐。油烟机未知不等于已关闭；具体故障降级需考虑真实风险。只有选择共同退出时，才以两区域无人且相关设备退出作为恢复条件；不用某一个雷达的 off 强制退出。
- 卧室：共用逻辑，按家庭选择床区、门帘、灯态和时段的组合；分别处理各输入先后变化。换人、传感器短暂抖动不应反复进出睡眠，不固定要求闭门/关帘。
- 观影/工作/洗浴：依据可靠状态和手动保持，保留必要任务照明；活动结束才恢复环境。共享热水器/新风等根据所有请求协调，不能一间房退出就关闭另一间仍需要的设备。
- 窗/雨/空调/新风：按机械风险与使用偏好互锁，风雨以本地传感器和可靠状态为依据；天气可用于预判但不能默默替代本地防雨保护。
- 清扫/晾衣架：清扫前后的窗帘恢复检查当前 owner；有人操作过就不覆盖。晾衣架位置、运动与人体保护按设备能力定义，不以“收到指令”宣称到位。
- 宠物设备：离线与恢复通知去抖；如获授权做断电恢复，设置持续时间、恢复供电的可靠截止时间、尝试上限与冷却。已离线不能切断未知身份的插座，上线也不应每次都重复触发投喂/清理。

## 感知与数值

每个输入带 value、health、observed_at、source。使用厂商观测时间判断天气新鲜；状态没变、最近下载成功不等于新观测。静态门磁长期不变也不自动等于过期。阈值按物理量和设备反馈加迟滞及稳定时间，不复制其他家庭的固定温度/瓦数。

占用融合原则：任一可靠的正向占用可证明有人；只有所有必需且健康的观测都明确无人并持续足够时间，才证明无人；其余未知。未配置必需传感器时使用事先选定的替代策略，而非让空集合 `all()` 意外通过。手机离线、BLE 丢失不能直接证明全屋离家，需考虑多人、访客和宠物。

## 并发与计时

以执行器或动作组为粒度设串行队列/owner；即使跨引擎也保持单一仲裁。不要在异步等待期间持有普通锁，也不要使用阻塞 sleep 或一个覆盖全家的大锁。

延迟任务记录业务键、generation、截止时间、发起原因和恢复策略。新的意图递增 generation，执行时重新核对令牌、当前条件与 owner。取消 scheduler 不会可靠撤回已经排队的回调。延迟步骤在每一步前重新检查，而不是只在第一步检查一次。

有跨重启要求的截止时间用绝对时间持久化；运行中短间隔可用单调时钟，日出/日期使用目标家庭时区并考虑夏令时。HA timer 的 restore 不保证为离线期间到期的任务补发 finished 事件，因此启动后对账。重载不能重置超时或重复注册监听；插件自动初始化时不要并行手动启动同一 App。

根据动作决定恢复策略：关某个已确认设备通常可以幂等对账；toggle、开锁、投喂和启动清扫不直接重放。记录 attempted 与 confirmed，失去确认后按业务决定人工处理或有限查询，不以盲重试达到“保证执行”。

## 多设备失败与恢复

记录每项动作预期状态、确认窗口、允许重试、超时出口与补偿。动作链有部分失败时保留成功部分证据，先判断补偿是否仍安全；无法确认窗已关时不得宣称相关保护完成。恢复旧亮度/模式之前确认仍由本次活动拥有，且没有更新的人工命令。

通知记录原因、影响与可执行处理；按严重性、重复抑制和恢复消息设计。iOS 重要警报/时效性等需实际客户端权限与用户偏好；不能把全部消息设为越过勿扰的最高等级。
